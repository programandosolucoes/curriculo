Correção de um falso positivo de conflito ao criar reserva DHCP estática dentro do pool principal, na API REST do pfSense.

PHPpfSenseAPI RESTDHCPVagrantmkdocs

O problema

Criar uma reserva DHCP estática com endereço dentro do pool primário era recusado pela API como conflito de endereço. O comportamento é legítimo em rede — reservar um IP que pertence ao pool é prática comum — e a validação estava rígida demais.

A arquitetura

O trabalho foi de leitura antes de escrita: entender a validação de sobreposição dentro de uma base de mais de três mil commits, isolar a condição que gerava o falso positivo e corrigir sem afrouxar as checagens que existem por bom motivo. O teste do próprio projeto, que codificava o comportamento errado, foi ajustado junto.

O resultado

Correção aplicada e validada em produção no firewall onde o problema apareceu. A correção é pública: o projeto é open source sob Apache 2.0 e a contribuição está no fork.
